# Регрессионное тестирование проекции тарифов и жизненного цикла

Тесты проверяют логику тарификации, парсинг временных окон UTC, сопоставление моделей и provider-aware разрешение ставок.

## Запуск тестов

```bash
npm test
```

## Проверяемые сценарии (`test/projection-lifecycle.test.mjs`)

1. **`hhmmToMinutes` и `parseWindow`**:
   - Корректный разбор диапазонов `HH:MM-HH:MM` в минуты от начала суток UTC.
   - Граничные условия: переход через полночь (`23:00-02:00`), пустые или невалидные строки.

2. **`slotOf`**:
   - Вычисление 30-минутного слота суток (`0..47`) на основе переданного timestamp.
   - Независимость накопления расхода от текущего момента времени (сохранение исторической ставки слота).

3. **`indexCatalog` и `matchModel`**:
   - Индексация моделей OpenRouter с поддержкой поиска без учета регистра.
   - Нормализация суффиксов вендоров и версий (например, `vendor/model:variant`).

4. **`resolveTariff` (Provider-aware)**:
   - Если указан `provider: "openrouter"`, плагин в первую очередь обращается к каталогу OpenRouter, даже если имя модели содержит `deepseek`.
   - Если провайдер не `openrouter` (или `deepseek`), DeepSeek модели тарифицируются по официальной зашитой сетке (пик / не-пик).
   - Ручные ставки `prices` из конфигурации имеют высший приоритет над внешними каталогами.
